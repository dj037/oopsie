# Oopsie Adults

> **把“我要出门做一件事”变成一份能执行的准备计划。**

<p align="center"><img src="public/assets/lobster-relaxed.png" alt="Oopsie 小龙虾" width="180"></p>

Oopsie 是面向日常外出场景的 Personal Agent 原型，帮助容易忘带物品、临出门匆忙的用户，将一句自然语言安排转化为可编辑的必带清单、准备时间轴和出发提醒，并通过逐项核对与行程复盘形成闭环。

## 项目亮点

- **从需求到产品机制：**围绕“物品容易遗漏、准备时间难估、提醒后缺少行动确认”三个问题，设计场景理解、计划生成、准备执行和复盘建议流程。
- **面向行动的 Agent 体验：**输入外出安排后，识别场景与时间信息，结合常带物品生成计划草稿；用户确认后再进入准备流程，保留修改权和确认权。
- **把强提醒落到任务上：**必带物品采用拍照识别后由用户确认的检查机制；清单有遗漏时，在出发环节明确提示。
- **个性化反馈：**根据实际准备与出发记录、遗漏反馈生成建议，帮助用户调整准备时长和常带物品。
- **小龙虾 IP 与时间反馈：**角色随出发倒计时切换悠闲、焦急和超时状态，让时间紧迫度更直观。

## 核心体验

1. 用一句话描述外出安排，例如“明天 9 点去公司汇报，地铁 40 分钟，要带自己的电脑”。
2. 查看并编辑场景推荐的必带/建议物品、准备时间轴与建议出发时间。
3. 打开当前行程的准备时钟，逐项拍摄识别并确认物品；清单状态与当前行程联动。
4. 查看遗漏确认、地图跳转、行程复盘、积分和常带物品设置。

当前推荐以可解释的场景规则和模板为主；没有配置外部 AI 时仍可使用。扫描使用服务端运行的本地 CLIP 视觉模型，识别结果是辅助核验，不代表能证明物品已装入包中。系统不读取用户其他应用的内容，也不伪造天气、路况或实时通勤数据。NFC 硬件流程未纳入当前版本。

## 技术实现

- **前端：**React、TypeScript、Vite，响应式 Web 界面和离线静态资源。
- **后端：**Node.js、Express、SQLite，提供账号会话、行程同步、积分账本、扫描凭证和可选的 AI 服务端代理。
- **图像识别：**Transformers.js / ONNX Runtime CPU 推理；模型在后端加载，照片只用于当前识别请求，不持久化保存。
- **移动端基础：**Capacitor iOS 工程已建立，接入原生相机和本地通知；需真机、Xcode 和签名环境进一步验证。
- **部署：**Netlify 托管 Web 前端，Render Node 服务运行 API；`netlify.toml` 和 `render.yaml` 提供初始部署配置。

## 本地运行

需要 Node.js 22.13+（推荐 Node.js 24）与 npm：

```bash
npm ci
npm run vision:setup  # 首次下载并校验视觉模型，约 147 MB
npm run dev
```

打开 `http://localhost:5173`。`npm run dev` 会同时启动 Vite 前端与本地 API。

常用检查：

```bash
npm test
npm run build
npm run build:server
```

## 云端部署

### Render API

将仓库连接到 Render 的 Blueprint，并检查 `render.yaml`。部署后端需要安装视觉模型；若平台要求付费，或服务因内存不足启动失败，请先停止，不要自动升级。

### Netlify Web

将仓库导入 Netlify，使用 `netlify.toml` 中的构建命令。配置环境变量 `OOPSIE_API_ORIGIN` 为 Render API 的 HTTPS 域名（不含路径）；在 Render 设置 `PUBLIC_ORIGIN` 为 Netlify 站点 HTTPS 地址。发布后检查 `https://<站点域名>/api/health`，再验证账号登录、行程同步与手机相机。

**部署注意：**当前云端部署是体验配置，线上可达性、相机、冷启动和视觉模型内存尚需目标平台实测。Render 免费实例可能休眠，临时 SQLite 数据可能丢失；Netlify 代理有单请求时限。网页提醒需要页面保持打开，不能保证锁屏强提醒。积分兑换目前只记录，不包含库存、实物配送或履约。

更详细步骤见 [`deploy/netlify.md`](deploy/netlify.md)。

## 数据与安全边界

- 使用私有仓库时，仓库内仍包含项目源代码。部署包不包含本地数据库、`.env` 密钥、研究材料、测试照片和介绍视频。
- 密码使用随机盐与 scrypt 哈希；登录会话使用 HttpOnly Cookie。正式面向公众开放前仍需补齐账号找回、账号注销、数据备份、滥用监控和隐私政策等工作。
- 使用本地视觉模型时，图片传给 Oopsie API 进行临时识别；只有明确配置外部视觉服务后，照片才会转发给该服务。

## 项目状态

本仓库对应一个可操作的早期体验版本，完成了 Web 端主要流程和本地集成检查。它不是已经验证过规模化运营的服务，也不是已上架 App Store 的 iOS 应用。建议先邀请小范围体验者验证清单建议是否有帮助、提醒是否及时、扫描确认是否易用，再决定接入持久化云数据库与正式账号体系。
